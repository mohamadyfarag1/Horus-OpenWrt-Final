# المعمارية الهندسية لنظام Horus-Spot الهجين (Captive Portal & Anti-Bypass System)

يوثق هذا المستند المرجع الهندسي الشامل والنهائي لنظام **Horus-Spot**، وهو نظام كابتف بورتال متطور وهجين مبني خصيصاً لفيرموير راوترات **Horus IPQ4019** في بيئة OpenWrt 24.10. تم تصميم هذا النظام ليعمل بتوافق كامل 100% مع سيرفرات **SAS4 (FreeRADIUS / MikroTik Profiles)** دون الحاجة لإجراء أي تعديلات على سيرفر SAS، مع تطبيق منظومة أمنية مشددة لسد كافة ثغرات التخطي والأبواب الخلفية.

## 2. آلية عمل المحرك الهجين (Hybrid RADIUS Engine)

يعتمد سيرفر **SAS4** على توليد سمات RADIUS مخصصة للميكروتيك (Vendor ID: 14988) عبر البرنامج التنفيذي `sas_auth`. يقوم سكريبت [`hybrid_mikrotik.uc`](../files_ap/usr/share/uspot/hybrid_mikrotik.uc) باعتراض حزمة `Access-Accept` وترجمتها لحظياً داخل ذاكرة الراوتر:

### أ. ترجمة سمة السرعة (`Mikrotik-Rate-Limit`)
- **الصيغة القادمة من SAS:** `rx-rate[/tx-rate] [rx-burst/tx-burst ...]`
- **قاعدة الترجمة الهندسية:**
  - في مصطلحات الميكروتيك:
    - `rx` = حركة مرور الصعود من العميل إلى الشبكة (Client Upload) $\rightarrow$ تُترجم إلى `rate_up` بالميجابت أو الكيلوبت/ثانية.
    - `tx` = حركة مرور الهبوط من الشبكة إلى العميل (Client Download) $\rightarrow$ تُترجم إلى `rate_down` بالميجابت أو الكيلوبت/ثانية.
  - يدعم المحرك كافة الوحدات القياسية: `k` (Kilobits), `M` (Megabits), `G` (Gigabits).
  - يتم تمرير هذه القيم مباشرة إلى جدول النواة (eBPF / Traffic Control Policer) لتحديد السرعة دون استهلاك للمعالج.

### ب. توقيت الجلسة والكوتا (`Session-Timeout` & `Quota`)
- يستخرج المحرك قيمة `Session-Timeout` بالثواني لضبط المؤقت الزمني للجلسة.
- يستخرج سمة الكوتا `Mikrotik-Total-Limit` (أو `ChilliSpot-Max-Total-Octets`) لمراقبة حجم البيانات الإجمالي المسموح به.
- يفرض المحرك إرسال تحديثات استهلاك دورية `Acct-Interim-Interval` كل **60 ثانية** لسيرفر الـ SAS لتظل عدادات لوحة التحكم متزامنة بدقة.

### ج. الفصل اللحظي للعملاء المنتهية باقاتهم (Instant CoA Disconnect)
- تستخدم خدمة `sas_dispoller` في الأوبونتو أداة `radclient` لإرسال حزمة `Disconnect-Request` (RFC 5176) على منفذ **3799**.
- يستمع راوتر Horus على منفذ `3799` بكلمة السر المشتركة (Shared Secret)، وبمجرد وصول أمر الفصل يتم محو سجل العميل (IP + MAC) فوراً من جداول الـ eBPF في أقل من **1 ملي ثانية**، مما يقطع الإنترنت فوراً دون الحاجة لإعادة تشغيل أو انتظار انتهاء الجلسة.

## 3. المنظومة الأمنية وسد الأبواب الخلفية (Anti-Bypass Hardening)

تمت برمجة قواعد جدار الحماية في الملف [`10-horus-spot-security.nft`](../files_ap/etc/nftables.d/10-horus-spot-security.nft) لتعمل على مستوى النواة (nftables / firewall4) وتضمن عدم وجود أي ثغرة للوصول للإنترنت قبل تسجيل الدخول:

| الثغرة المحتملة | كيفية استغلالها | آلية الحماية وسد الثغرة في Horus-Spot |
| :--- | :--- | :--- |
| **نفق الـ DNS (DNS Tunneling)** | استخدام برامج مثل `iodine` لإرسال بيانات مشفرة داخل استفسارات DNS عبر بورت 53 لسيرفر خارجي. | **الاعتراض الإجباري (Strict DNS Hijack):** تحويل كل استفسارات UDP/TCP 53 قسراً إلى خادم الراوتر الداخلي (`127.0.0.1:53`)، وإسقاط أي حزمة موجهة لسيرفرات DNS خارجية (مثل 8.8.8.8) تماماً. |
| **تسريب الـ IPv6 (IPv6 Leak)** | استغلال عدم فلترة IPv6 في بعض أنظمة الكابتف بورتال للمرور للإنترنت مجاناً. | **إسقاط تام للـ IPv6 Forwarding:** إسقاط أي حركة مرور IPv6 متجهة للـ WAN للأجهزة غير المسجلة دخول، مع تعطيل إعلانات الـ RDNSS غير الضرورية على البريدج. |
| **تسريب بروتوكولات UDP / QUIC** | استخدام بروتوكول HTTP/3 (UDP 443) أو بورتات الألعاب لتجاوز حظر الـ TCP. | **قفل منافذ الـ UDP:** إسقاط كافة حزم UDP 443 و UDP 80 المتجهة للـ WAN قبل المصادقة، مما يجبر كافة المتصفحات على الرجوع لبروتوكول TCP ليتم توجيهها لصفحة الدخول. |
| **نفق الـ Ping (ICMP Tunneling)** | تمرير بيانات الإنترنت داخل حزم الـ Echo Request/Reply لبروتوكول ICMP. | **حظر ICMP للإنترنت:** حظر الـ Ping المتجه للـ WAN من الأجهزة غير المسجلة، والسماح به فقط داخل الشبكة المحلية للراوتر للتأكد من الاتصال. |
| **انتحال الماك والأي بي (Spoofing)** | تغيير ماك الجهاز لأحد المشتركين النشطين المتصلين حالياً لسحب إنترنت باسمه. | **الربط الثلاثي المقفل (Triple Binding in eBPF):** لا يمرر فلتر eBPF أي بايت إلا إذا تطابق: `(IP + MAC + Interface)`. أي اختلاف بين الماك والـ IP يُسقط الحزمة فوراً في النواة. |

## 4. مكونات الواجهة الرسومية (LuCI Horus-Spot UI)

تتميز الواجهة بتصميم حديث كلياً (Client-Side Rendering via JavaScript) متطابق تماماً مع أنماط ثيمات OpenWrt (Argon و Bootstrap):

1. **Horus Spot Settings:**
   - تمكين أو تعطيل البوابة بالكامل.
   - اختيار كارت الشبكة ومنافذ العمل (Port 3990).
   - **قائمة المواقع المسموحة (Walled Garden):** إمكانية إضافة أيبيهات وسيرفرات مسموح تصفحها مجاناً بدون تسجيل الدخول (مثل أي بي لوحة SAS، أو بوابة دفع إلكتروني).
2. **NAS (RADIUS):**
   - إعداد السيرفر الأساسي والاحتياطي (IP, Port 1812/1813, Secret).
   - إعدادات NAS ID و NAS IP لتعريف الراوتر لدى SAS.
   - إعداد منفذ الـ CoA (3799) وكلمة السر المشتركة.
3. **Portal Pages (مدير الصفحات):**
   - أداة متقدمة لتصفح ورفع وتنزيل صفحات الدخول (HTML, CSS, Images) المخزنة في مسار `/www/uspot/` بضغطة زر.
4. **Connected Clients (جدول المتصلين الحي):**
   - استعراض مباشر لجميع الأجهزة المتصلة والمتزامنة مع النواة:
     - عنوان الماك (MAC Address).
     - عنوان الأي بي (IP Address).
     - حالة الحساب (State / Authenticated).
     - حجم البيانات المستهلكة رفعاً وتنزيلًا (Bytes Rx / Tx).
5. **Advanced Config (المحرر المباشر):**
   - محرر نصوص خام يفتح ملف التكوين `/etc/config/uspot`.
   - يتيح كتابة وحفظ أي بارامترات متقدمة مع زر حفظ وإعادة تشغيل الخدمة تلقائياً.

## 5. دليل التحقق الميداني واختبار الجودة (Verification & Testing)

للتأكد من عمل المنظومة بأعلى أداء بعد تفليش الراوتر:

1. **فحص تشغيل النواة والموديولات:**
   ```bash
   lsmod | grep -E "sch_bpf|act_police"
   ubus call uspot status
   ```
2. **فحص سد ثغرات الـ DNS من جهاز متصل غير مسجل دخول:**
   ```bash
   # يجب أن يُحوّل قسراً للراوتر الداخلي أو يفشل، ولا يجب أن يصل لـ 8.8.8.8
   nslookup google.com 8.8.8.8
   ```
3. **فحص استقبال وتطبيق السرعات من SAS:**
   ```bash
   # قراءة جداول الـ TC المطبقة على الكروت
   tc -s qdisc show dev br-lan
   ```
4. **فحص أوامر الفصل اللحظي (CoA):**
   ```bash
   # إرسال طلب فصل تجريبي من سيرفر SAS
   echo "User-Name = user1" | radclient -x <ROUTER_IP>:3799 disconnect <SHARED_SECRET>
   ```
