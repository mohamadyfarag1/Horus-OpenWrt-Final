# توثيق إضافة (LuCI App RADIUS Sync)

هذا المستند يشرح معمارية وطريقة عمل إضافة `luci-app-radius-sync` المبرمجة خصيصاً لأنظمة OpenWrt. هذه الإضافة تهدف إلى دمج بيانات المشتركين الموجودة في سيرفرات (RADIUS) مع حالة الأجهزة المتصلة فعلياً بالراوتر، وعرضها في واجهة مراقبة احترافية (Dashboard).

---

## 1. الهيكل المعماري للإضافة (Architecture)
تم تصميم الإضافة وفق المعايير القياسية لـ (OpenWrt LuCI MVC) مع محرك خلفي (Daemon) بلغة بايثون للحفاظ على سرعة الراوتر وفاعليته.

```text
luci-app-radius-sync/
├── Makefile                               # ملف البناء القياسي لـ OpenWrt
├── luasrc/
│   ├── controller/radius_sync.lua         # المتحكم: يسجل مسارات القوائم ويوفر API لواجهة الـ AJAX
│   ├── model/cbi/radius_sync/settings.lua # النموذج: واجهة إعدادات السيرفر (SAS, DMA, ADV, ICM)
│   └── view/radius_sync/dashboard.htm     # العرض: لوحة تحكم تفاعلية تقرأ البيانات دون إعادة تحميل
└── root/
    ├── etc/
    │   ├── config/radius_sync             # الإعدادات المخزنة بصيغة UCI
    │   └── init.d/radius_sync             # خدمة التشغيل التلقائي مع بدء النظام (Auto-start)
    └── usr/
        ├── bin/radius-sync-daemon.py      # سكريبت بايثون الذكي لجمع الماكات والتواصل مع الريديوس
        └── share/rpcd/acl.d/              # تصاريح النظام للسماح للواجهة بقراءة ملف البيانات
```

---

## 2. كيف تعمل الإضافة؟ (Workflow)

1. **إدخال الإعدادات (Settings):** 
   يدخل المستخدم عبر واجهة الراوتر لاختيار نوع سيرفر الريديوس (مثلاً SAS)، ويدخل (IP, Username, Password/API Key). وتُحفظ هذه البيانات في ملف `/etc/config/radius_sync`.

2. **التجميع المحلي (Local Scanning):**
   كل 60 ثانية (قابل للتعديل)، يستيقظ السكريبت الخلفي `radius-sync-daemon.py`، ويسأل الراوتر عن الأجهزة المتصلة حالياً باستخدام أوامر مثل:
   - `arp -a` لمعرفة أجهزة اللان.
   - `iwinfo` لمعرفة أجهزة الواي فاي.

3. **الاستعلام الذكي (On-Demand Fetching):**
   بدلاً من جلب كامل قاعدة بيانات الريديوس، يقوم سكريبت البايثون بتجميع (ماكات) الأجهزة المتصلة فقط، ويرسلها في طلب `HTTP POST` مجمع (Batch Request) إلى سيرفر الريديوس.

4. **الدمج والحفظ (Merge & Cache):**
   يقوم الريديوس بالرد ببيانات هذه الماكات فقط (اسم المشترك، الجيجات المتبقية، حالة الحساب). يقوم البايثون بدمج هذه البيانات مع بيانات الراوتر (IP، Interface) وحفظها في ملف مؤقت `/tmp/radius_users.json`.

5. **العرض الحي (Live Dashboard):**
   واجهة `dashboard.htm` تستخدم لغة Javascript لسحب محتويات الملف المؤقت كل 5 ثوانٍ، وتحديث الجدول أمام المستخدم بشكل لحظي وبطريقة تفاعلية وأنيقة.

---

## 3. تفاصيل الـ API للأنظمة الأربعة (تحت التطوير)

سكريبت البايثون مصمم ليكون (Modular) ليدعم 4 أنظمة، وهي حالياً معدة كقوالب (Stubs) جاهزة لاستقبال مسارات الـ API الحقيقية:

### أ. SAS Radius
- يعتمد على `Bearer Token`.
- سيعتمد على مسار استعلام بالماك (Mac-Lookup).

### ب. DMA Radius
- يعتمد على `API Key`.
- يتصل بـ DMA APIs الخاصة بجلب كوتة المشترك.

### ج. ADV Radius
- يعتمد على `master_key` و `session_token`.

### د. ICM Radius
- يعتمد على مصادقة مخصصة ببيانات الدخول.

---

## 4. كيف يتم بناء هذه الإضافة في السوفتوير؟
في مجلد المشروع الرئيسي، تم تعديل سكربتات البناء التلقائي:
- `scripts/05-configure.sh`: يقوم بنسخ مجلد الإضافة إلى مسار `package/luci-app-radius-sync` وتفعيلها في الـ `.config`.
- `scripts/02-patch-makefiles.sh`: يقوم بإجبار نظام الـ Image Builder على دمج حزمة `luci-app-radius-sync` بالإضافة إلى بيئة تشغيل البايثون `python3-light` ومكتبات `json` و `urllib` لتكون جزءاً أساسياً لا يتجزأ من روم المصنع (Sysupgrade) الخاص براوتر Horus 9200.

## 5. الخطوات القادمة (Roadmap)
1. تجربة الباكدج على السوفتوير الجديد للتأكد من ظهور القوائم وعمل لوحة التحكم بشكل سليم.
2. مراجعة دوال بايثون (`query_radius`) لاستبدال الداتا الوهمية (Mock Data) بأكواد طلبات (HTTP Requests) فعلية للأنظمة الأربعة.
